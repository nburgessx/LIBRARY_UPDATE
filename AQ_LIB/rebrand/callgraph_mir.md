# 0.5 — `mir*` call-graph & disposition

**Conclusion: `mir*` is a self-contained legacy binding stack with no inbound
dependency from `aq`/`me` code. Remove it wholesale.**

## What `mir*` is

A parallel Interest-Rates binding API (headers dated 2016, "Swig interface to
Java", author J. Ye). Three layers, all `mir`-only:

```
AQ_BINDINGS\source\mir*.cpp/.h   (58 files, ~45 exported functions + overloads)
        │  calls
        ▼
validation\include|src\tryMir*   (~35 files: tryMir<Fn>)
        │  calls
        ▼
etrading / models                (shared core — NOT mir-specific)
```

Plus **156 `mir*` functions in the XLL `LAXL.cpp`** (`.APPLES\...\MLIBQ_ADDIN`)
— the "LAXL" legacy Excel layer is essentially the `mir` add-in. Never ported to
`AQ_XLL`, so "removing" them = not carrying them.

## Disposition

**Delete, in Phase 1.4:**

- `src\AQ_BINDINGS\source\mir*.cpp` and `mir*.h` — 58 files
- `src\validation\include\tryMir*.h` and `src\validation\src\tryMir*.cpp` — ~35 files
  (`tryMirAssetSwapSpread, tryMirClearEntityPool, tryMirCompound, tryMirGetAnnuity,
  tryMirGetBusinessDays, tryMirGetDate, tryMirGetDateFromTerm, tryMirGetDF,
  tryMirGetECBStartDate, tryMirGetForwardRate, tryMirGetIMMDate, tryMirGetNextCBDate,
  tryMirGetNextECBDate, tryMirGetParRate, tryMirGetPCAResults, tryMirGetTerm,
  tryMirGetZeroRate, tryMirInterpolation, tryMirOISParRate, tryMirOISSwapPV,
  tryMirSetUpBasisSwapCurve, tryMirSetUpFwdFXConstantCurve, tryMirSetUpOISCurve,
  tryMirSetupPCA, tryMirSetUpSwapCurve, tryMirSwapDuration, tryMirSwapDV01,
  tryMirSwapPV, tryMirSwapSchedule, tryMirSwapStubRate`)
- `mir*` project entries in `validation.vcxproj` / `.filters` and
  `AQ_BINDINGS.vcxproj` / `.filters`
- `mir*` lines in `swig_CSharp.i`, `swig_JAVA.i`, `swig_Python.i`, `swig_R.i`,
  and `swig_R_wrap.cpp`
- fix the two error-message string literals (drop `mirCurveGenerate` wording)
- update the two `@brief` doc headers in the `tryMe*` files (or they get caught
  in the Phase 3 rename anyway)
- `LAXL.cpp`'s 156 `mir*` functions are simply not ported into `AQ_XLL`

**Functionality check before deleting:** a few `mir*` names look like they *might*
be the only exposure of some capability (`mirSetupPCA` / `mirGetPCAResults` —
principal-component analysis; `mirCurveGenerate`). Confirm the equivalent is
reachable via a `me*`/`aq*` path (there is a `meUtilityPCA` binding and
`meCurveCalibrate*` set — likely yes). If any capability is **only** in `mir`,
promote that one to `aq` instead of dropping it. Otherwise: clean delete.
